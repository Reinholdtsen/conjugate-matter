*The gate is the shell script [`scripts/check.sh`](../../../scripts/check.sh), which runs the repository's twelve verification scripts in `verify/` and then the wiki's own consistency check, and exits with a failure if any check fails. The project calls it "the definition of done": work is not finished until it passes, and a check may not be weakened to make it pass. Each verification script prints one line per check, a pass or a fail together with the measured value where there is one, so the record of a run shows what was tested as well as the verdict. What the gate tests is the arithmetic of the models the scripts encode, whether the notes on the literature check and on the dual sector report their stored records, and the form of the wiki; which claims it covers, and which it leaves to derivation, review or nothing, is listed below.*

**Status:** Method, in force — untagged — root [`CLAUDE.md`](../../../CLAUDE.md) ('The gate'); the results it checks carry [V] where the papers cite them. In the run of 2026-10-21 every check passed and the script ended "OK — all checks pass."

## The rule

Root [`CLAUDE.md`](../../../CLAUDE.md), 'The gate': "[`scripts/check.sh`](../../../scripts/check.sh) is the definition of done. It runs every script in `verify/`, then [`scripts/check-wiki.py`](../../../scripts/check-wiki.py) on the wiki, and exits non-zero on any failure. It must pass before work is called finished. Do not weaken a check to make it pass. New verification scripts get wired into it." The script's own header: "The definition of done for this repo. Exits non-zero if any verification script fails. New arbitration and audit scripts in verify/ get added here."

The gate is where [the iron rule](iron-rule.md) becomes enforceable. A number that a current document asserts gets a check in a script, and the script runs every time the gate runs, so a later edit to a script that changes a computed number, or a change of environment that changes the arithmetic, shows up as a failure. Ten of the scripts hold their own copies of the figures they compare against and do not read the documents, so an edit to a document's figure does not trip them. The eleventh, [`verify/literature_check.py`](../../../verify/literature_check.py), reads [`notes/literature-check.md`](../../../notes/literature-check.md) and flags 64–69 of [`review/wiki-build-flags.md`](../../../review/wiki-build-flags.md), flag 64's addendum among them; its scan of the flags file stops at the heading of the dual-sector investigation's flags, and it fails unless the span holds flags 64–69 and no other item: an edit to a verdict or a count in the note's two tables, to a quotation in the note or in those flags, or to the authors, year, volume or page of one of the note's references trips it, as does a change to a title that brings its word overlap with the snapshot's title below 0.7 (a small change can pass), or to one of the counts the script recomputes from the record and looks for in the note's prose, at the one place where it looks for each; the note's other statements of these counts and of the tables' counts, and its other counts, among them the queries that did not run, are not checked ([the literature-check script](literature-check-script.md)). Its section G is a calculation like those of the other scripts, the algebra behind flag 66, with its anchors in published equations: those of scale-factor duality with sources, of Friedmann cosmology and of a solution of Brans–Dicke gravity, in which a scalar field sets the strength of gravity. The twelfth, [`verify/dual_sector.py`](../../../verify/dual_sector.py), reads [`notes/dual-sector.md`](../../../notes/dual-sector.md), the page on [dark matter as the dual Standard Model](../../dark-matter/conjugate-matter/dual-standard-model.md), the only wiki page a script in `verify/` reads, and flag 64's addendum and flags 70–73: an edit that leaves a quotation in any of them found neither in another repository document nor among the quotations stored in [`review/dual-sector/quotes.json`](../../../review/dual-sector/quotes.json) trips it, as does an edit to the authors, title, year or link of one of the note's references, to one of the dates it checks, or to one of the counts it recomputes from the record and looks for in the note's prose ([the dual-sector script](dual-sector-script.md)). Its section F is a calculation too: the bracket of the doubled phase space that the note sets beside the program's single phase space, built from the zero-mode commutators of [Minic 2020](https://arxiv.org/abs/2003.00318) (eq. 27).

## How it runs

- **Environment.** The scripts run in a Python virtual environment, `.venv`, built from [`requirements.txt`](../../../requirements.txt), which pins numpy==2.5.4 and sympy==1.14.0. Without it the gate prints `check FAILED: no .venv. Create it with:` and the command to create it, and exits with status 1.
- **An explicit list.** The script runs [`verify/battery.py`](../../../verify/battery.py), [`verify/soliton_obituary.py`](../../../verify/soliton_obituary.py), [`verify/toy_coset.py`](../../../verify/toy_coset.py), [`verify/toy_gw.py`](../../../verify/toy_gw.py), [`verify/toy_s4.py`](../../../verify/toy_s4.py), [`verify/toy_s5.py`](../../../verify/toy_s5.py), [`verify/phase_space_diameter.py`](../../../verify/phase_space_diameter.py), [`verify/closed_universe.py`](../../../verify/closed_universe.py), [`verify/velocity_gated_gravity.py`](../../../verify/velocity_gated_gravity.py), [`verify/gate_mechanism.py`](../../../verify/gate_mechanism.py), [`verify/literature_check.py`](../../../verify/literature_check.py) and [`verify/dual_sector.py`](../../../verify/dual_sector.py), in that order, named one by one rather than matched by a pattern. "Runs every script in `verify/`" therefore holds as long as the list matches the folder, as it does now; a new script counts only once it is added to the list. When the wiki was built, root [`CLAUDE.md`](../../../CLAUDE.md)'s 'Layout' named only `battery.py` and `soliton_obituary.py` of the six scripts then in the list (flag 38 in [`review/wiki-build-flags.md`](../../../review/wiki-build-flags.md)); it now names all twelve. The list in the script is the fact.
- **Every script runs.** The shell options are `set -uo pipefail`, without `-e`. A failing script prints its name followed by `FAILED` and sets a status variable; the loop continues, so one run reports every failure rather than the first.
- **Then the wiki.** After the twelve scripts it runs [`scripts/check-wiki.py`](../../../scripts/check-wiki.py) on the whole wiki, with the same failure handling.
- **The verdict.** If nothing failed it prints "OK — all checks pass." and exits 0; otherwise it exits 1.
- **Deterministic.** Every script that draws random numbers fixes its seeds, so a rerun in the pinned environment prints the same values, apart from the elapsed times that [`verify/closed_universe.py`](../../../verify/closed_universe.py), [`verify/velocity_gated_gravity.py`](../../../verify/velocity_gated_gravity.py) and [`verify/gate_mechanism.py`](../../../verify/gate_mechanism.py) print. [`verify/toy_s4.py`](../../../verify/toy_s4.py) says so in its docstring: "Fixed seeds, so the run is deterministic."

## The check line

All twelve verification scripts define the same helper, `check(name, ok, detail="")`. It prints `PASS` or `FAIL`, the check's name and, when a detail is given, the measured value in square brackets, and it records the failure. At the end a script with failures prints `FAILED`, the count and the names, and exits with status 1; a clean script prints a closing "OK" line of its own. Lines indented without a verdict print measured values for the reader (the T4 limits, the Monte Carlo rows, the truncation sweep) and gate nothing by themselves. [`verify/battery.py`](../../../verify/battery.py) states the convention: "Every verdict is a boolean or a number against a tolerance, never a judgement."

Two kinds of check need distinguishing:

- a check against something known independently of the documents, an [independent anchor](independent-anchors.md), or a property the derivation predicts (a symmetry, a sign, a scaling);
- a check labelled "parity" or "quoted:", which compares the output with the figure a document prints. It confirms that the document prints what the code computes and that the environment still reproduces it. It is a reproduction, and by itself it tests nothing about whether the figure is right.

- **The literature check's judgments.** [`verify/literature_check.py`](../../../verify/literature_check.py) takes the agents' labels as given; its docstring: "It does not test the agents' judgments of how close a paper comes to a conjecture; the verifiers and the panel tested those." - **The dual-sector investigation's judgments.** [`verify/dual_sector.py`](../../../verify/dual_sector.py) takes the verifiers' and the panel's verdicts as given; its docstring: "It does not test the agents' judgments of how close a paper comes to a conjecture; the verifiers and the panel tested those." ## The wiki check

[`scripts/check-wiki.py`](../../../scripts/check-wiki.py) applies the conventions of [`wiki/CLAUDE.md`](../../CLAUDE.md) to every page. Its docstring lists the checks in order of severity:

- **link** — an internal link points at a page that does not exist, or is not an absolute /wiki/ link;
- **anchor** — a link points at a heading that does not exist, with each heading's anchor computed the way Hugo computes it;
- **heading** — a heading holds a link, an image, a bare web address, emphasis or an attribute block such as `{#id}`, for which Hugo builds the anchor from only part of the heading's text or takes it from the block, so the script cannot compute it;
- **map** — a page is not linked from its parent section's index;
- **source** — a frontmatter source, or a repository path in inline code, names a missing file;
- **frontmatter**, **weight**, **section** — missing or invalid fields, siblings sharing a weight, a folder without an index, a file named claude.md, or two files that serve at one address;
- **gist**, **statusline** — the page's opening: the italic passage and the status line;
- **status** — a page's title or status line disagrees with its status, or the page is missing from the register of that status;
- **voice** — wording that tells how a claim's status came about instead of the claim, a person named other than P.R. outside [the collaboration](../collaboration.md) and the home page, or a current-version tag on a citation of #11 outside the history pages ([`wiki/CLAUDE.md`](../../CLAUDE.md), 'State the claim, not the discussion');
- **summary** — the [executive summary](../../summary.md) passes 800 words, links a dead or under-review page, or leaves out P.R.'s conjectures;
- **star** — an unescaped starred symbol such as v\*, whose asterisk can end an italic passage early;
- **h1**, **fence** — no top-level heading, and a language on every code fence;
- **acronym** — an acronym that is unregistered, or used without its expansion nearby or a link (registry: [`scripts/wiki-acronyms.txt`](../../../scripts/wiki-acronyms.txt)).
- **symbol** — a page that uses the [equation of state](../../cosmology/dark-energy/quintessence.md#dark-energy-and-the-equation-of-state) w, pressure divided by energy density, its parameters w₀, [the value today](../../cosmology/dark-energy/cpl-parametrization.md#what-w-and-wₐ-mean), and wₐ, how fast w changes as the universe expands, or the [redshift](../../cosmology/scale-factor-duality/redshift.md) z, the stretching of light by the expansion (larger z is earlier), without the words of that definition within about 180 characters of its first use. A link does not count. The glossary and the notation page, whose entries define each symbol, are not checked, and the script lists the pages on which the letter stands for another quantity ([`wiki/CLAUDE.md`](../../CLAUDE.md), 'Symbols').
- **paper** — a paper identifier in prose (`arXiv:…`, `doi:…` or a handle) that is not a link to the paper; a paper link not in canonical form, or to an identifier that the registry [`scripts/wiki-papers.tsv`](../../../scripts/wiki-papers.tsv) lacks; or a link whose label names another identifier, names neither the paper's identifier (an INSPIRE record as "INSPIRE N") nor its registered first author, or gives a year the registry does not list for the paper. The registry records each linked paper's first author and years; [`scripts/wiki-papers.py`](../../../scripts/wiki-papers.py) builds it from INSPIRE, arXiv and Crossref, which needs the network, while the check runs offline ([`wiki/CLAUDE.md`](../../CLAUDE.md), 'Links').

Its reason for existing, from the docstring: "Hugo does not validate internal links: it renders /wiki/does-not-exist without complaint. This script catches a dead link in the Markdown, before any build." Two later checks belong to the gate of the site that publishes the wiki, `npm run check` in `site/` (`site/CLAUDE.md`): the build fails on a link to a missing page, and [`scripts/check-site.py`](../../../scripts/check-site.py) checks the built pages, among other things that every heading got the anchor this script computes. Given file names, it reports only on those files while resolving links across the whole wiki; with `--stats` it also prints status counts and the pages with fewer than three inbound links from outside their parent's map.

It checks form, not content. It does not compare a page's numbers, quotations, tags or statuses with the source documents; that comparison was the work of the wiki build's verifiers, whose suspected source errors are in [`review/wiki-build-flags.md`](../../../review/wiki-build-flags.md) with executed checks in [`review/wiki-build-checks/`](../../../review/wiki-build-checks/). Its paper check compares each link's label with the registry, not what a page says with what the paper says.
